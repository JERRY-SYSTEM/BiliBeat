# iOS 长时间后台播放回归

## 定位与修复

原生队列的 `_prefetchNext` 持续追加下一首，但旧实现只裁剪当前歌曲之后的项目，从未释放之前的音频源。顺序播放长歌单时，原生队列随已播放歌曲数量增长。现在在预加载之前释放旧音频源，保留上一首、当前歌曲和下一首，完整逻辑歌单不受裁剪影响。修改原生队列或跳转前等待裁剪完成，避免索引偏移。

这可以解释资源压力，但尚无故障设备的崩溃日志，因此不能确认搜索框闪退是文件描述符耗尽、内存终止还是独立的原生异常。不要将代码层面的修复等同于真机故障已经复现并消除。

相关防护：控制中心使用 CDN 缩略图及 Referer，本地封面使用 file URI；回前台重发媒体信息；图片下载有超时和请求中断，回前台可重试失败封面；取色失败也会释放图像及解码器；缓存归属提前索引，文件大小异步读取并保留快照，扫描失败可以重试。

## 自动化

在 Flutter SDK 可用的环境执行：

```sh
flutter pub get
flutter analyze
flutter test test/audio_player_handler_test.dart test/cache_inventory_test.dart
flutter test
```

新增测试模拟 250 首自动连续切歌，断言原生队列不超过三个项目、逻辑索引和歌曲正确、播放 Future 没有中断，并验证上一首、删除窗口外的歌曲及远距离跳转。Fake player 模拟原生播放器在前缀删除后保持当前音频源；这不能替代 AVPlayer 真机验证。

## 真机验证

1. 使用至少 250 首不同歌曲的长歌单，先下载音频，顺序循环播放。用 Instruments 记录内存、分配和打开的文件；可先每首 seek 到末尾加速检查，再锁屏连续播放数小时。
2. 确认原生音频源不会随歌曲累计增长。反复使用控制中心上一首、下一首、暂停、继续；确认声音、标题、进度、封面始终属于同一首歌。
3. 播放时切换网络、短暂断网，再解锁回前台。检查主页图片、缓存页面，以及聚焦搜索框后输入和提交搜索。
4. 检查单曲循环、随机播放、快速多次跳转、播放结束、队列删除和拖动排序，特别是删除已经播放并移出原生窗口的歌曲。
5. 若仍闪退，保留对应构建的 dSYM，导出设备 `.ips` 崩溃日志或 JetsamEvent，并记录后台时长、切歌数、歌单大小和网络状态。用日志区分资源终止与原生异常。
